Nudges

Nudges are real: they go to each task owner's email address, which comes from the People directory (or is set by hand on the task). Use "Send test" on a saved channel to check it works, then switch on automatic nudges below. Secrets you save here are never shown again in full.
Add / update a nudge channel
Slack: message each owner directly, or post in one channel
  1. Direct message to each owner (recommended): at api.slack.com/apps create an app for your workspace → OAuth & Permissions → add the bot scopes chat:write and users:read.email → Install to Workspace → copy the Bot User OAuth Token (starts xoxb-) into the field below. Owners are found by their email, so their Slack email must match the People directory.
  2. One shared channel instead: in the same app turn on Incoming Webhooks → Add New Webhook → pick the channel, and paste the https://hooks.slack.com/... URL. Messages name the owner but aren't private.
  3. Works on Slack's free plan.
Teams: needs a Microsoft 365 work or school account
  1. Post in a channel: in Teams, open the channel's "..." menu → Workflows → "Post to a channel when a webhook request is received" → finish the steps and copy the URL it gives you into the field below.
  2. Message each owner directly: in Power Automate, create a flow with the trigger "When a Teams webhook request is received" and the action "Post message in a chat or channel" (Post as: Flow bot, Post in: Chat with Flow bot), with Recipient set to recipient_email and Message set to text from the request body. Paste the flow's URL below.
  3. Personal (free) Teams accounts don't support Workflows, so they can't receive these.
Email: any SMTP server — Gmail works for free
  1. Gmail: turn on 2-Step Verification for the account, then create an App password. Use server smtp.gmail.com, port 587, STARTTLS, your Gmail address as user name and "from", and the 16-character app password (not your normal password). Gmail allows roughly 500 emails a day.
  2. Microsoft 365 / Outlook: smtp.office365.com, port 587, STARTTLS — your admin must allow "Authenticated SMTP" for the mailbox.
  3. Email services (SendGrid, Resend, Postmark…): use the SMTP host, port and credentials from their dashboard.

How to get your Jira details
  1. Log in to Atlassian and go to API tokens.
  2. Click "Create API token", name it, and copy it — that's the API token below.
  3. Your base URL is the address you use for Jira, e.g. https://yourteam.atlassian.net.
  4. Find your project key under Project Settings → Details (a short code like ENG or OPS).
How to get your Google Sheets details
  1. In the Google Cloud console, create (or pick) a project and enable the "Google Sheets API" for it.
  2. Under Credentials, create an OAuth Client ID of type "Desktop app" and download its JSON — save it into the commitment-tracker folder (filename starting client_secret_).
  3. From a terminal in that folder, run python google_oauth_setup.py once — it opens a browser, you approve access, and it saves a local token. No further login needed after that.
  4. Create (or open) a Google Sheet under the same Google account and copy its spreadsheet ID from the URL — the long string between /d/ and /edit.
Every new commitment (uploaded, captured live, or added by hand) is written to the sheet as soon as it's created, and status changes made in this app update the sheet's Status column. Turn off to sync by hand instead.
Current tracker
Two-way sync — every field: the sheet has the columns ID, Task, Owner, Due date, Status and Owner email (A–F). Any change made here (task, owner, owner email, due date, status) rewrites that row in the sheet; any change made in columns B–F of the sheet flows back here. The most recent edit wins: an edit older than the app's last change to that task is ignored and the sheet is put back to the app's version. An owner typed in the sheet without an email is matched from People, and the email is filled in for you. For changes made in the sheet to reach the app, point it at your signed tracker webhook (see Webhook security below for the signing secret): POST /api/webhooks/tracker-update/…
Body (signed with the X-CT-Timestamp and X-CT-Signature headers; send any of the fields):
{ "external_ref": "row-2", "task": "…", "owner": "Kevin Heys", "owner_email": "kevin@x.com", "due_date": "2026-10-31", "status": "Done", "edited_at": 1760500000, "provider": "google_sheets" }

Webhook security

            

                Anything that pushes data into this app — the Google Sheet script, a transcript automation — must sign each request
                with your account's signing secret. Unsigned, wrongly signed, more than
                5 minutes old, or repeated (replayed) requests are refused, and each webhook URL
                accepts at most 60 requests a minute. Fathom uses its own signature (the secret saved above)
                with the same replay checks.
            

            

                
Signing secret

                

                

                    ••••
                    
                    
                    
                

                

                    Treat it like a password. Rotating makes a new one and the old one stops working immediately — update your
                    Apps Script / automation right after.
                


                
How to sign a request

                

                    Send these headers with the JSON body, where signature is the hex HMAC-SHA256 of
                    "<timestamp>.<exact body>" keyed with the signing secret:
                

                
X-CT-Timestamp: 1760500000          (unix seconds, now)
X-CT-Signature: v1=<signature>
X-CT-Delivery:  <a unique id>      (optional, recommended)
