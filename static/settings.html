Nudges

This is a prototype: nudges are logged, not sent. Webhook URLs / API keys you enter here are stored per your email so the settings shape is realistic, but no outbound request is ever made to Slack, Teams, or email.
Add / update a nudge channel
How to get a Slack webhook URL
  1. Go to api.slack.com/apps and create (or open) an app for your workspace.
  2. Turn on "Incoming Webhooks", then click "Add New Webhook to Workspace".
  3. Pick the channel that should receive nudges and authorize it.
  4. Copy the generated URL (starts with https://hooks.slack.com/services/...) into the field below.
How to get a Teams webhook URL
  1. In the Teams channel that should receive nudges, open the "..." menu → Connectors (or Workflows on newer Teams).
  2. Add an "Incoming Webhook" connector and give it a name.
  3. Copy the URL it generates into the field below.
How to get an email API key
  1. Sign up with a transactional email provider (e.g. Resend, SendGrid, Postmark).
  2. Create an API key with send permission.
  3. Paste that key into the field below.

Task tracker

Also a prototype: syncing here is simulated, not sent to Jira or Google Sheets — no outbound API call is made. If you don't connect a tracker, commitments are tracked in this app only, exactly as before.
Connect where you already track tasks
How to get your Jira details
  1. Log in to Atlassian and go to API tokens.
  2. Click "Create API token", name it, and copy it — that's the API token below.
  3. Your base URL is the address you use for Jira, e.g. https://yourteam.atlassian.net.
  4. Find your project key under Project Settings → Details (a short code like ENG or OPS).
How to get your Google Sheets details
  1. Open the Google Cloud console and create (or pick) a project.
  2. Enable the "Google Sheets API" for that project.
  3. Create credentials — an API key, or a service account (with a JSON key) if you want write access.
  4. If you used a service account, share the target spreadsheet with its email address.
  5. Copy the spreadsheet ID from its URL — the long string between /d/ and /edit.
Current tracker
Two-way sync: status changes made here push to the tracker (mocked, above). For changes made in Jira or the sheet to flow back here, point an automation at: POST /api/webhooks/tracker-update
Body:
{ "email": "you@company.com", "external_ref": "ENG-142", "status": "done", "provider": "jira" }
  1. Jira: Project Settings → Automation → new rule, trigger "Issue transitioned", action "Send web request" to the URL above with that JSON body (map the issue key to external_ref).
  2. Google Sheets: Extensions → Apps Script → add an onEdit trigger that POSTs the same body when a status cell changes.
A commitment gets an external_ref the first time you sync it to the tracker — use the "Simulate update from tracker" button on a commitment to try this without setting up a real automation.

Transcript source

"Check now" is still simulated. Once a source below is connected, a real automation can also push a transcript straight into this app the moment a meeting ends — see the webhook box below. No parser is wired in yet, so it lands as an unprocessed transcript (same as an upload), with commitments still added by hand. Whatever you pick here, you can always upload a transcript manually from the dashboard.
Where should transcripts come from?
How to get your Zoom details
  1. Go to the Zoom App Marketplace and sign in with the Zoom account whose meetings you want captured.
  2. Under "Develop", build a Server-to-Server OAuth app. Copy its Account ID, Client ID, and Client Secret into the fields below.
  3. Grant it the cloud_recording:read scope so it can read meeting transcripts.
  4. Add an event subscription for recording.transcript_completed, set a Secret Token for it (paste that below too), and — once you've saved this form — point its Event notification endpoint URL at the webhook URL shown further down this page.
How to get your Google Meet details
  1. Meet transcripts save to Google Drive/Docs after a recorded meeting.
  2. In the Google Cloud console, enable the Drive API for a project.
  3. Create an API key or service account with access to your Workspace transcripts.
  4. Enter your Workspace account email and that API key below.
How to get your Teams details
  1. In the Azure portal, register an app under Azure Active Directory.
  2. Grant it the OnlineMeetingTranscript.Read.All Graph API permission (needs admin consent).
  3. Copy your Tenant ID from the Azure AD overview page.
  4. Generate a client secret to use as the API key below.
How to get your Otter.ai details
  1. Log in to otter.ai and go to Settings → Integrations.
  2. Generate an API key for your account (available on eligible plans).
  3. Enter your Otter account email and that API key below.
Live capture: once a source above is saved and enabled, a real "meeting ended" automation (Zoom's event subscription, or your own script for a Custom app) can push the transcript straight into this app instead of waiting on "check now". Point it at: POST /api/webhooks/transcript-capture/…
Body (for a generic/Custom push):
{ "title": "Weekly Standup", "meeting_date": "2026-09-03", "transcript_excerpt": "..." }
Honest caveat: this only works once this app is reachable at a public HTTPS URL a real automation can call — it's localhost-only today. Use "Simulate incoming transcript" below to try the flow without one.
