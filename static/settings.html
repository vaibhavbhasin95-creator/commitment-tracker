Nudges

Nudges are real: they go to each task owner's email address, which comes from the People directory (or is set by hand on the task). Use "Send test" on a saved channel to check it works, then switch on automatic nudges below. Secrets you save here are never shown again in full.
Add / update a nudge channel
Slack: message each owner directly, or post in one channel
  1. Direct message to each owner (recommended): at api.slack.com/apps create an app for your workspace → OAuth & Permissions → add the bot scopes chat:write and users:read.email → Install to Workspace → copy the Bot User OAuth Token (starts xoxb-) into the field below. Owners are found by their email, so their Slack email must match the People directory.
  2. One shared channel instead: in the same app turn on Incoming Webhooks → Add New Webhook → pick the channel, and paste the https://hooks.slack.com/... URL. Messages name the owner but aren't private.
  3. Works on Slack's free plan.
Teams: needs a Microsoft 365 work or school account
  1. Post in a channel: in Teams, open the channel's "..." menu → Workflows → "Post to a channel when a webhook request is received" → finish the steps and copy the URL it gives you into the field below.
  2. Message each owner directly: in Power Automate, create a flow with the trigger "When a Teams webhook request is received" and the action "Post message in a chat or channel" (Post as: Flow bot, Post in: Chat with Flow bot), with Recipient set to recipient_email and Message set to text from the request body. Paste the flow's URL below.
  3. Personal (free) Teams accounts don't support Workflows, so they can't receive these.
Email: any SMTP server — Gmail works for free
  1. Gmail: turn on 2-Step Verification for the account, then create an App password. Use server smtp.gmail.com, port 587, STARTTLS, your Gmail address as user name and "from", and the 16-character app password (not your normal password). Gmail allows roughly 500 emails a day.
  2. Microsoft 365 / Outlook: smtp.office365.com, port 587, STARTTLS — your admin must allow "Authenticated SMTP" for the mailbox.
  3. Email services (SendGrid, Resend, Postmark…): use the SMTP host, port and credentials from their dashboard.

Task tracker

Jira and Custom stay simulated here (no outbound call). Google Sheets is real: syncing appends an actual row via the Sheets API, using a one-time local OAuth login — see python google_oauth_setup.py. If you don't connect a tracker, commitments are tracked in this app only, exactly as before.
Connect where you already track tasks
How to get your Jira details
  1. Log in to Atlassian and go to API tokens.
  2. Click "Create API token", name it, and copy it — that's the API token below.
  3. Your base URL is the address you use for Jira, e.g. https://yourteam.atlassian.net.
  4. Find your project key under Project Settings → Details (a short code like ENG or OPS).
How to get your Google Sheets details
  1. In the Google Cloud console, create (or pick) a project and enable the "Google Sheets API" for it.
  2. Under Credentials, create an OAuth Client ID of type "Desktop app" and download its JSON — save it into the commitment-tracker folder (filename starting client_secret_).
  3. From a terminal in that folder, run python google_oauth_setup.py once — it opens a browser, you approve access, and it saves a local token. No further login needed after that.
  4. Create (or open) a Google Sheet under the same Google account and copy its spreadsheet ID from the URL — the long string between /d/ and /edit.
Every new commitment (uploaded, captured live, or added by hand) is written to the sheet as soon as it's created, and status changes made in this app update the sheet's Status column. Turn off to sync by hand instead.
Current tracker
Two-way sync: status changes made here push to the tracker (mocked, above). For changes made in Jira or the sheet to flow back here, point an automation at: POST /api/webhooks/tracker-update
Body:
{ "email": "you@company.com", "external_ref": "ENG-142", "status": "done", "provider": "jira" }
  1. Jira: Project Settings → Automation → new rule, trigger "Issue transitioned", action "Send web request" to the URL above with that JSON body (map the issue key to external_ref).
  2. Google Sheets: in the sheet, Extensions → Apps Script, paste this, then use the clock icon (Triggers) → Add Trigger → function onStatusEdit, event source "From spreadsheet", event type "On edit" — a plain onEdit(e) function can't make outbound calls, this needs to be an installable trigger: 
    function onStatusEdit(e) {
  if (!e || !e.range) return; // only runs from the On edit trigger
  var STATUS_COLUMN = 5; // column E — the app writes ID, Task, Owner, Due date, Status to A:E
  var range = e.range;
  if (range.getColumn() !== STATUS_COLUMN || range.getRow() === 1) return; // row 1 is the header
  sendStatus(range.getRow(), range.getValue().toString());
}

function sendStatus(row, status) {
  var APP_URL = "https://YOUR-NGROK-URL/api/webhooks/tracker-update";
  var YOUR_EMAIL = "you@example.com";
  var response = UrlFetchApp.fetch(APP_URL, {
    method: "post",
    contentType: "application/json",
    muteHttpExceptions: true,
    headers: { "ngrok-skip-browser-warning": "true" },
    payload: JSON.stringify({
      email: YOUR_EMAIL,
      external_ref: "row-" + row,
      status: status, // "Done", "Closed", "In progress", "Open"... are all accepted
      provider: "google_sheets",
    }),
  });
  Logger.log(response.getResponseCode() + " " + response.getContentText());
}

// Run by hand from the editor to test the connection (row 2 = first data row).
function testStatusEdit() {
  sendStatus(2, "Done");
}

Transcript source

"Check now" is still simulated. Fathom is real: its webhook pushes a transcript straight into this app the moment a meeting ends, and it's parsed and extracted automatically — see the webhook box below. Zoom / Google Meet / Teams / Otter here stay simulated (see readme for why). Whatever you pick here, you can always upload a transcript manually from the dashboard.
Where should transcripts come from?
How to get your Zoom details
  1. Go to the Zoom App Marketplace and sign in with the Zoom account whose meetings you want captured.
  2. Under "Develop", build a Server-to-Server OAuth app. Copy its Account ID, Client ID, and Client Secret into the fields below.
  3. Grant it the cloud_recording:read scope so it can read meeting transcripts.
  4. Add an event subscription for recording.transcript_completed, set a Secret Token for it (paste that below too), and — once you've saved this form — point its Event notification endpoint URL at the webhook URL shown further down this page.
How to get your Google Meet details
  1. Meet transcripts save to Google Drive/Docs after a recorded meeting.
  2. In the Google Cloud console, enable the Drive API for a project.
  3. Create an API key or service account with access to your Workspace transcripts.
  4. Enter your Workspace account email and that API key below.
How to get your Teams details
  1. In the Azure portal, register an app under Azure Active Directory.
  2. Grant it the OnlineMeetingTranscript.Read.All Graph API permission (needs admin consent).
  3. Copy your Tenant ID from the Azure AD overview page.
  4. Generate a client secret to use as the API key below.
How to get your Otter.ai details
  1. Log in to otter.ai and go to Settings → Integrations.
  2. Generate an API key for your account (available on eligible plans).
  3. Enter your Otter account email and that API key below.
How to get your Fathom webhook secret
  1. Sign up free at fathom.video and connect your calendar so its bot joins your Zoom meetings automatically.
  2. Go to Settings → API Access and generate an API key.
  3. Save this form first — it generates the webhook URL shown further down this page.
  4. Back in Fathom, add a webhook pointed at that URL. Enable "include transcript", and pick a trigger such as "my recordings".
  5. Fathom shows a webhook secret (starts with whsec_) when the webhook is created — paste it below.
Live capture: once a source above is saved and enabled, a real "meeting ended" automation (Zoom's event subscription, or your own script for a Custom app) can push the transcript straight into this app instead of waiting on "check now". Point it at: POST /api/webhooks/transcript-capture/…
Body (for a generic/Custom push):
{ "title": "Weekly Standup", "meeting_date": "2026-09-03", "transcript_excerpt": "..." }
Honest caveat: this only works once this app is reachable at a public HTTPS URL a real automation can call — it's localhost-only today. Use "Simulate incoming transcript" below to try the flow without one.
